# Run 27 ExecPlan — Target-Check Evidence Bridge

## Objective

Implement Phase 3 of the approved evolution roadmap: a read-only
`target-check-evidence` adapter that lets `sah verify` consume a schema-valid
`sah-loop-checks` outcome without executing arbitrary commands.

## Authority and constraints

- Repository `AGENTS.md`, indexed validation documents, ADR-0010/0014/0021/0023, the
  iteration outcome schema, and the accepted Phase 3 ADR remain authoritative. The supplied
  evolution document is proposal input.
- Existing filesystem and TypeScript adapters, verification result semantics, S12/S13 gates,
  and v0.4/v0.5 bundle loading remain compatible.
- The adapter requires an explicit target-relative check-record path and caller-supplied target
  revision. It compares the outcome's exact target revision, bundle fingerprint, target cwd,
  executor, check ID, status, exit code, and digest shape; it never runs the command or judges
  test adequacy.
- Unknown, duplicate, stale, unsupported, or mismatched evidence is incomplete/unsupported and
  never pass. Malformed, unsafe, missing, or unreadable record input is operational-error.
- Do not implement benchmark automation, model provenance, stable trigger IDs, hosted storage,
  UI, database behavior, or sandbox-safe CLI hardening in this run.
- Do not commit, push, or create a PR without explicit user authorization. Phase 2 was already
  committed separately at `77da2eb`.

## Accepted design

Add `--check-record <target-relative-json>` and `--target-revision <revision>` to `verify`, plus
matching library options. `verifyBundle` loads one confined regular iteration-outcome file,
validates it with the existing schema registry, and prepares an in-process adapter. A constraint
using `factSource=iteration-check-record`, `predicate=required-check-passed`, and a check ID
selector receives a pass only when the unique recorded result has status `passed`, exit code `0`,
matching target revision/design fingerprint/cwd, the `sah-loop-checks` executor, and valid output
digests. The result says only that the recorded check passed in the bound context; adequacy remains
assisted/judgment evidence.

## Implementation slices

1. Add the adapter and confined outcome loader; extend the observable fact-source vocabulary
   explicitly without rewriting existing bundle artifacts.
2. Wire verification options, CLI parsing/help, public library exports, and deterministic result
   diagnostics while preserving existing adapter dispatch and record publication.
3. Add target-check fixture/test helpers and regression, stale-context, unknown/duplicate,
   malformed/path-safety, CLI, and existing-adapter compatibility tests.
4. Add ADR/docs/skill guidance and run the full source-checkout quality suite plus diff/schema/doc
   self-review.

## Acceptance checks

- A check record generated by `sah loop-checks` can satisfy one declared deterministic constraint
  when the exact revision, design fingerprint, target cwd, check ID, status, exit code, and
  digests match.
- Missing/unknown/duplicate check, stale revision/fingerprint, wrong cwd/executor, non-zero exit,
  malformed JSON, unsafe path, and schema-invalid outcome never return a pass.
- `verify` still does not execute the check-record command; existing filesystem/TypeScript checks
  and S13 eligibility rules remain unchanged.
- Schema traces, format, lint, typecheck, tests, build, CLI smoke, `git diff --check`, links, and
  line budgets pass.
